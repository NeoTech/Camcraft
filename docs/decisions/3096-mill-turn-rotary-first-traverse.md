## #3096 - A rotary kind on the spindle C answers to the live-tool first-traverse law

- **What was decided** (taken unattended; the maintainer can change it):
  1. **The post's real order is the lathe's.** A rotary kind (`Mode::Rotary`: Rotary Contour, Parallel, Offset) whose fitted line is the machine's C gets its path stamped with C (`rotary_gate::stamp_spindle_c`). The stream of that path carries `PARAM LiveTool`, and the post engine refuses by name each post that does not declare `liveTooling` (`crates/post/src/post/engine.rs`). Only `fanuc-lathe.cps` declares it, so the mill post (`fanuc.cps`, the mill-turn's default) never writes such a program. The lathe post's `liveMove` writes `G00 C` with the turret at its index position, then `G00 X Z` to the first motion record. That is the order of #3077's cross drill, so the law is `verify::live_first_traverse`, called from the new seam `operation/rotary_traverse.rs` in the two rotary arms of `generate.rs`, right after the C stamp.
  2. **The premise of the maintainer.** The unknown start is at the top of the travel (the tool-change height: the turret's index position, the top of the X and Z travel), as in #2965, #2987, #3077 and #3083. **NOT covered:** a program that starts with the turret low near the work, the chuck or a steady, for example after a manual jog. The operator must send the turret to its index position before the program starts.
  3. **The work turns with C; fixed steel does not.** C stands at the first point's angle before X and Z move. So the stock, the parts and the turning steel (a chuck) are read in the part frame about the first point's own radius, exactly (#3077's swept solid). The fixed steel (a tailstock, a steady, the table) is read in the machine frame, where the station is the +X half-plane of the spindle line: the convention of `verify::c_steel` (#486) for the same kinds. The seam calls the law a second time with a start on the +X station and the fixed boxes as steel that stands still there.
  4. **Both ends of the first move are judged**, as for the cross drill: the end (where `liveMove` goes) and the start (for a post that goes to the stated start).
  5. **A hit is a refusal by name** (`GenError::Invalid`, the kind's label first). It blocks the generation, so nothing posts. No warning variant, as #3077.
  6. **Which machines.** The law answers where the path states C and `first_traverse::mill_order` is false: a mill-turn or a lathe. A mill keeps #2965's swept law.
  7. **An unstamped rotary kind on a mill-turn takes the mill laws.** A machine file that states no axis line for its rotaries gives no C stamp (`rotary_gate::rotary_letter` answers `None`). That path has no `PARAM LiveTool`, so the mill post writes it in the mill order (Z, then X/Y, then the rotary words), the premise of #2965's swept law. `rotary_traverse::mill_post_rotary` adds it to `mill_order` at the call in `generate.rs`. Before this no law judged it.
  8. **Caches read Stale once.** `current_stamp` writes `live-traverse-rotary-3096` for each rotary kind on a lathe or a mill-turn setup (`rotary_traverse::newly_judged_on`). No mill's stamp moves; the global salt stays. No shipped example, catalog project or golden holds a rotary kind on a lathe or a mill-turn (scout read of `examples/`, `docs/tester-kits/` and `crates/app/tests/golden/`), so none reads Stale. The goldens `c_axis_helix.nc` and `c_axis_unwind.nc` post a hand-made path and do not pass through generation.
  9. **The spindle line has one source.** `rotary_gate::c_center` gives the line that C turns about; the stamp and the law both read it.
  10. **Test fixtures (decided by the coordinator).** The shared C-axis bar fixture (box stock 14 x 14 x 34, top Z34; Rotary Contour clearance 25; BN-0600, r 3) opened with a first record at r 2.000, Z28.000, inside the box stock: the posted `G00 X Z` went into uncut stock, and the law refuses it. The fixtures in `c_axis_live`, `c_axis_fixture`, `lathe_work_spindle`, `lathe_workholding_live` and `rotary_letter` take clearance 40 (as `c_axis_unwind` already did), which keeps what each test pins. `c_axis_unwind::a_rewind_through_stock_is_convicted_by_the_verifier` needs its orbit on a clearance plane inside the stock, and its first record stands on that plane too, so no mill-turn stock can hold the orbit and clear the first rapid. It now asserts the mill-turn's refusal by name, then reads the verifier's orbit conviction (`RapidInStock`) on the same bench declared a mill, where #2965's swept law reports `FirstTraverseLow`. Dropped: move the stock (more readings change); expect only the refusal (loses the verifier coverage); drop the override (changes the test's intent).
- **Why.** Prime Directive: a first rapid through the stock, a part or the steel must be refused by name. Before this, no law judged the first rapid of a rotary kind on a mill-turn.
- **Considered and dropped.**
  - Judge the mill post's order (Z, then X/Y, then C; `fanuc.cps` `xyFirst`) for the stamped path: that post refuses the stamped path by name, so the order is never posted. Judging it would refuse legal work (decision #3083 item 4) and leave the order that is posted unjudged.
  - Read the fixed steel revolved about the spindle (#3077's reading for the cross drill): stricter, but it refuses a steady that stands opposite the station at every C. The station is a fixed machine place (`c_steel`), so the exact read is correct here.
  - Reuse `cross_traverse::judge` with a label: its texts name holes and a chuck/table split that reads the fixed steel revolved. A seam of its own keeps the cross drill's texts and readings unchanged.
- **Known limits** (as #3077): the turret body and its other stations are not modelled (the widest band of the tool stack runs on past its end); the tool's cross-section is read square; the stated X/Z travel is not used.
- **Cost to change later**: low. `operation/rotary_traverse.rs`, two calls in `generate.rs`, one stamp word.
