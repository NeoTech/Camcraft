## #3081 - A 3+2 tool axis that points down toward the table gets a verdict that blocks the post

- **What was decided** (taken unattended; the maintainer can change it):
  1. **A new verdict, `Warning::FirstTraverseUnderTable { at, height_mm, limit_mm }`.** Past a 90-degree head tilt the tool axis points down toward the machine table (`axis_z < 0`). A higher plane along that axis stands lower in the world, so the repair is the opposite of the `FirstTraverseLow` repair. The new variant says "lower the clearance plane to Z<limit> or under it" and never "raise". It blocks the post (it is not in the advisory list of `Warning::blocks_post`). It replaces the note of #2987 ("...the tool axis points down toward the table...").
  2. **The same premise as #2987 (premise (b), maintainer decision of 2026-11-20).** The unknown start is any point of the X/Y travel at the tool-change height, the top of the Z travel (table top plus `stroke`). The worst start is the one with the LOWEST reading `low` along the axis: the move from it to the plane drops `(plane - low) * -axis_z` in the world. The plane is refused when that drop is more than `stroke + Z_TOL`. The highest plane that every such move keeps over the table top is `limit = low + stroke / -axis_z`, and the verdict names it.
     - **NOT covered:** a program that starts with the tool low near the table or the work, for example after a manual jog. The operator must send the machine to its tool-change height before the program starts, as for the upright law and #2987.
  3. **Two verdicts can stand together.** The stock and fixture verdict (`FirstTraverseLow`, "raise") and the table verdict ("lower") are judged apart and both go into the warnings. When the limit is under the stock top along the axis, no plane is clear from the tool-change height, and the two verdicts say so together. The UI folds the new verdict on its own line, key 224: the opposite repair of key 221. Key 222 is taken by open PR #2836 (`UndercutLift`) and 223 by open PR #3062 (`DrillUndersize`), so 224 collides with neither.
  4. **Tilted caches read Stale once.** The post gate trusts the warnings that a cache carries. A tilted cache judged under the old law holds the note and no verdict, so `current_stamp` writes the salt `first-traverse-table-3081` for each operation with a tilt (`OpParams::tilt()`). Only those operations regenerate; the global salt stays.
  5. **MCP.** `mcp/job.rs` `finding` names the kind `first_traverse_under_table`, with `blocks_post: true`. No new command, so no new MCP tool.
- **Why.** A refusal must name the right repair (Prime Directive: a visible refusal, never a silent pass). The note of #2987 did not block the post, so a first rapid into the table on a past-90 head tilt could post.
- **Considered and dropped.**
  - Refuse with the `FirstTraverseLow` "raise" verdict: its height is wrong for a down-pointing axis, and a refusal with a wrong repair misleads.
  - A new boolean field on `FirstTraverseLow`: the enum is a file format (project v3 cache), and a new field breaks old caches. A new variant is additive.
  - Bump the global stamp salt (`camcraft-op-stamp-v5`): every cache in every project reads Stale for a law that only reads tilted planes.
  - Keep the note beside the verdict: the verdict says all that the note said, and the repair too.
- **Not judged (known).** As #2987: the law runs at generation only; a mixed machine and a head tilt with a vertical work C keep the #2987 limits.
- **Cost to change later**: low. One arm of `table_read` and the push in `judge` (`operation/first_traverse.rs`), one `Warning` variant and its text.
