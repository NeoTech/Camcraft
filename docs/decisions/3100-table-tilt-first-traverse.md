## #3100 - The first traverse of a 3+2 plane and a cross drill on a machine whose table tilts

- **What was decided** (issue worker, unattended; the maintainer can change it):
  1. **The premise (maintainer, PR #2997).** The unknown start is at the top of the Z travel (the tool-change height), as for #2901, #2965, #2987 and #3084. A program that starts with the tool low near the table or the work (for example after a manual jog) is NOT covered.
  2. **The post order is the basis.** `fanuc.cps` sends Z (`traverseZ`), then X/Y at that height (`xyFirst`), then the move with the rotary words (`onRapid`, the `tilt()` words on the same `G00`). A 3+2 plane and a cross drill post in that order too. So during the X/Y traverse each rotary that turns the work stands where the previous program left it, and the #2987 law (which reads the work at the operation's own pose) is not enough.
  3. **Who answers now.** The posed law of #3084 (`first_traverse_posed::turn_of`) reads, besides the multi-axis and rotary kinds, each kind that carries a `Tilt` (the 3+2 planes: Face, Contour, Pocket, Adaptive 2D and the others of `OpParams::tilt`) and the cross drill (`OpParams::Drill` with a cross set). Only in the mill order (`mill_order`, a mill or a mill-turn's mill post), and only on a machine with a tilting rotary that states `turns_part: true`. The pose set, the WCS-origin premise of the lines and the refusal by name of a lone rotary with no line are #3084's, unchanged.
  4. **The machine table.** A table never turns (`fixture::workholding_for`). On a machine where every tilting rotary turns the work, the posed law reads the table fixed where it stands: its top as a machine height over the WCS origin, in the path's height scale (`table_top`). Where a head tilts, the #2987 table law reads it, as before. The coordinator accepted the fixed read (the table does not turn; a swept travel box refuses every 3+2 program). When the stock rests on the table, the stock's posed top is never under the table top (a stock point on the table top keeps at least that height in the pose zero), so this read refuses nothing more today. It keeps the table judged and not silently left out.
  5. **The verdict.** The same blocking `Warning::FirstTraverseLow` (#2901). The higher of the posed work top and the table top is named; it replaces each first-traverse verdict at a lower top.
  6. **The post's declared order (coordinator decision, after the batch gate on #3142).** `tormach.cps` turns A at the safe Z (`G53 G0 Z`, then `G0 A`) at each section's first motion, and only then makes the first X/Y traverse. So under it the X/Y traverse never runs at a pose the previous program left, and the posed law over-read: it refused `tilt_a180_routes` and `tilt_basis0_edited_file` (a 50 x 50 bar on the A line, clearance 10 over its top: the corner sweeps to 35.355 over Z35). The order is now a capability the post script DECLARES, as `liveTooling` is: `rotariesBeforeTraverse = true` (`post::dialect::turns_rotaries_first`). The setup's post is read when the job is collected (`first_traverse_posed::post_order`, once per script text). When the post declares it, the posed law does not read the operation (for every posed kind, the #3084 multi-axis kinds included); the #2987 law reads it at its own pose. A post that does not declare it (every other built-in, every user script without it, a script that does not load) reads the strict way: never looser. Three conditions:
     - **Backed by a pin.** `posting_rotaries_first.rs` posts three indexed slots through `tormach.cps` and asserts, in each section, `G53 G0 Z` then `G0 A` before the first X/Y word. A registry check asserts that Tormach PathPilot is the only shipped post that declares it, so a new declaring post fails until it has its own order test.
     - **A user's own script is taken at its word, never silently.** A `PostRef::File` script that declares it puts a note on the path: "First traverse: judged at the operation's own pose, because the post script declares rotariesBeforeTraverse ... taken at its word".
     - **The stamp follows the declaration.** The #3084 word is written only when the posed law reads the operation (`newly_judged` = the law applies and the post does not declare the order). A change of the setup's post, or of its script's declaration, moves the stamp. A user's own declaring script also writes the word `first-traverse-declared-3100` (Opus safety review of a4d2ac019): an operation generated under Tormach PathPilot reads Stale after the setup takes a user's copy of the script, and its regenerate puts the note on the path. The declaration cache keeps at most 32 script texts.
  7. **Cache.** The op stamp word of #3084 (`first-traverse-posed-3084`) comes from the same `newly_judged` selection. So a 3+2 or cross-drill cache on such a machine under a strict post takes the word and reads Stale once. Under a declaring post (Tormach PathPilot) the stamp of a 3+2 operation is as before this change. So `examples/first-4axis-part.camproj` (Tormach PathPilot) keeps its stamps: the restamp of the first version of this PR is dropped. A #3084 multi-axis kind under Tormach PathPilot on a work-turning machine loses the word and reads Stale once.
- **Test change.** `first_traverse_table.rs` `a_work_turning_rotary_keeps_the_table_under_the_work` pinned "no verdict" for a B 30 face 20 over the plane origin on a trunnion (A and B turn the work). The block's corner now reads on its sphere (29.584 along the B axis), so that plane is held by name (by the stock, not the table). The test now asserts that verdict, and that a plane 30 over the origin passes. Its machine now sets the WCS origin to zero (on the lines). The coordinator accepted this change (a test fixture).
- **Pinning tests.** `crates/app/tests/first_traverse_table_tilt.rs`: `a_3_2_plane_under_the_work_a_turning_table_can_leave_turned_up_is_refused_by_name`, `a_3_2_plane_over_every_pose_of_a_turning_table_passes`, `a_post_that_turns_the_table_first_reads_the_plane_at_its_own_pose`, `a_users_own_post_is_taken_at_its_declared_order_with_a_note` (with the negative: the same script without the declaration is held by name), `a_switch_to_a_users_declaring_post_reads_stale_and_regenerates_with_the_note`. `crates/app/tests/posting_rotaries_first.rs`: `only_the_tormach_post_declares_that_it_turns_the_rotaries_first`, `the_tormach_post_turns_a_at_safe_z_before_each_first_xy_traverse`. `tilt_a180_routes` and `tilt_basis0_edited_file` stay unchanged and pass because the Tormach post declares the order. The changed `first_traverse_table.rs` test. Unit test `the_fixed_table_reads_its_top_in_the_paths_height_scale`.
- **Known limits.**
  - The premise of item 1.
  - A user's own script that declares `rotariesBeforeTraverse` and does not keep that order is not caught: its declaration is taken at its word (with the note). The swing of the rotaries at the safe Z is the index-swing clause's.
  - A cross drill on a mill-turn is read only when its machine states a tilting rotary that turns the work. A spindle C stated along Z does not tilt. The one shipped mill-turn file, `assets/machines/millturn.mch`, states one rotary, C along [0, 0, 1], with the head under it; so no shipped mill-turn reads the posed law, and the cross drill has no end-to-end pin (coordinator decision).
  - An upright operation (no `Tilt`) on a table-tilt machine posts no rotary words, so the table stays where the previous program left it for the whole operation. That is not a first-traverse question and is not read here.
  - The #3084 limits (lines through the WCS origin, the Z word read as a machine height, the tool radius not added) hold.
- **What was considered and dropped**:
  - Read the machine table through every pose (as turning steel): a table box spans the X/Y travel, so its swept top would refuse every 3+2 program, and the table does not turn.
  - Read every pose under every post (the first version of this PR): it refuses legal programs of the shipped microARC 4 with its own post.
  - A check of the post's NAME (skip the law for "Tormach PathPilot"): a user's copy of the script, or a changed script, would not follow it; the declaration lives in the script and is pinned to its real order.
  - Raise the clearance of the two red fixtures: it keeps the false refusal in the product.
  - A refusal of every 3+2 plane on a table-tilt machine: it blocks programs that the law shows to be safe.
  - A new stamp word: the #3084 word already moves each newly judged cache once.
- **Cost to change later**: low. The selection is `first_traverse_posed::posed_kind`; the table read is `table_top` and `table_stays`; the declaration is one manifest flag (`post::dialect::turns_rotaries_first`) and `first_traverse_posed::post_order`.
