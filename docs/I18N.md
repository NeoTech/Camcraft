# Interface languages (#853 pilot)

This branch carries a working, reviewable pilot of the multi-language direction
asked for in [#853](https://github.com/NeoTech/Camcraft/issues/853). It is not
the finished feature: it is the architecture, one complete language
(Simplified Chinese), the font that makes it drawable, and the tests that keep
it honest. Languages are declared in one registry in `crates/i18n`: adding one
is a catalogue file plus a row, not a new branch in the lookup or the picker.

Try it:

```sh
cargo run --release -p camcraft-ui          # follows the system locale
CAMCRAFT_LANG=zh-CN cargo run --release -p camcraft-ui   # or name one
```

The language follows the system locale on first start (`LC_ALL`, then
`LC_MESSAGES`, then `LANG`; a Chinese locale selects Chinese). The View
door's **Language** list switches live and remembers the choice in
`prefs.json` beside the theme: *Follow system* (the default, no key written)
or a pinned language. `CAMCRAFT_LANG` takes a BCP 47 tag (`zh`, `zh_CN`,
`zh-Hans`) and overrides both for that run; an unknown tag is logged and
ignored, so the stored preference (or, with none, the locale) applies. Nothing changes for English users: the source language
installs no font and translates no string, so its window is byte-identical to
before this branch.

## Architecture

| Piece | Where | Role |
| --- | --- | --- |
| Catalogue + lookup | `crates/i18n` | a one-row-per-language `REGISTRY`, `Lang`, `Catalog`, `tr`, `tf`, `tr_in`, `count`, `set_lang`, `system_lang`, `init_from_env` |
| The picker + its memory | `egui_app/layout/mod.rs`, `state_prefs.rs`, `app/prefs.rs` | View door rows, `select_language`, `prefs.json`'s `language` key |
| The catalogue | `assets/i18n/zh-CN.toml` | `"English source" = "translation"`, one pair a line |
| The font | `assets/ui/fonts/NotoSansSC-Regular-Subset.ttf` | Noto Sans SC 400, GB2312 + punctuation, 2.3 MB, OFL 1.1 |
| Font wiring | `crates/ui/src/egui_app/fonts.rs` | installs the face for a translated language, nothing for English |
| Translator workflow | `assets/i18n/README.md`, `scripts/i18n/check.py` | edit text, check it, no build needed |
| Font build | `scripts/fonts/subset_sc.py` | reproducible subset from the upstream variable font |

**English is the key.** Every lookup is keyed by the English string the code
already writes, so a miss shows English, never a key or a blank, and a wording
change degrades to English until a translator follows it. This is the
gettext-shaped answer to #853's open question 2, chosen because it needs no new
dependency and no rewriting of 4 600 call sites; if the maintainer prefers
Fluent, only `crates/i18n` changes - the call sites all say `tr`/`tr!`.

## What is translated in this pilot

Five seams cover the surfaces a user reads most:

| Seam | File | What it covers |
| --- | --- | --- |
| Property grid labels | `egui_app/layout/form.rs` (`label_cell`, `group`, `action_bar`) | every `prop_row` / `check_row` / group header / footer verb in every page |
| Model tree | `egui_app/browser_tree.rs` (`t_row`) | section headers and literal rows; user names never pass through |
| Ribbon | `egui_app/panes.rs` (`text_of`, `caption`, dropdown rows, machine tabs) | 22 cells, section doors, group captions, workspace tabs |
| Operation tabs | `egui_app/op_tabs.rs` | Geometry / Heights / Passes / Lead in / Lead out / Feeds / Machine |
| Page details | `op_page.rs`, `geo_page.rs`, `machine_page.rs`, `browser_pane.rs` | heading, type line, coolant/source, pick mode, WCS footer buttons |

3 638 strings ship in `zh-CN.toml`. Earlier batches covered the ribbon, tree,
tool kinds, machine tabs, property vocabulary, hover hints, consequence lines,
direct egui literals and `format!` templates (`tf`). This batch closes the
status-line and refusal seams that had escaped the earlier scans: status
sentences in `state.rs` and the `state_*` modules, page labels built with
`format!`, and the timed import/refresh line. The catalogue key is the English
template, so a translation can move the arguments.

Deliberately **not** translated (the remaining work, below): protocol output
(G-code, CL, project files, `.mch`/`.cps`), MCP names and JSON, log lines agents
parse and test goldens. Refusal **codes** that `starts_with()` matches are
kept in English as stable identity; their displayed sentence is translated
and the match accepts either form, with a test pinning both (see
`is_profile_refusal`). Value strings that carry no words (a machine name, a
coolant mode) and dock panel titles, whose `Tab::title` is also an id, are
also left alone.

## How the layout survives

The worry is real but the measurement says it is small, and mostly in the other
direction: Chinese labels are narrower at the same size.

- Ribbon cells are a fixed `Tokens::cell_w` (76 × 30 px, floor 40 px at a
  1280-point window). Measured at 11 px with the bundled font, the **English**
  operation captions already overflow the cell's 74 px in 13 of 42 cases
  (`Multi-Axis Contour` = 101 px); their Chinese translations measure 33–55 px.
- `painted::cell` shrinks a label down to `font_label_min` and only then
  ellipsizes, so a shorter translation simply reads whole. The one thing that
  cannot happen is a label bleeding into its neighbour.
- Everything else is egui's content-driven layout; the whole UI hardcodes fewer
  than 30 explicit pixel sizes, and the property grid already truncates with a
  hover that carries the full text.

The tests pin this: `every_chinese_ribbon_caption_fits_its_cell` measures every
ribbon string against the cell, and `the_chinese_ribbon_is_narrower_than_the_
english_one` asserts the aggregate direction.

The one thing that would look like "the layout broke" - two faces mixed inside
one line, jumping the baseline - is avoided by putting the CJK face first in
`Proportional` for a translated language, so Latin, digits and hanzi share one
face and one line height.

## Fonts and licences

`assets/ui/fonts/NotoSansSC-Regular-Subset.ttf` is built by
`scripts/fonts/subset_sc.py` from Noto Sans SC (SIL OFL 1.1, licence in
`assets/ui/fonts/OFL.txt`, notice in `assets/ui/LICENSES.md`). The subset holds
ASCII, Latin-1, general/CJK punctuation, fullwidth forms, letterlike symbols,
arrows, geometric shapes and the 6 763 GB2312 hanzi: 8 090 code points, 2.3 MB.
A rare hanzi outside GB2312 falls back to a box; every shipped string is inside
the set, which the font test proves by reading the TTF's `cmap` directly.

## Tests

```sh
cargo test -p camcraft-i18n
cargo test -p camcraft-ui --lib fonts::
cargo test -p camcraft-ui --lib i18n_tests
```

- `crates/i18n/src/tests.rs` - the file reads clean, English is the source, a
  miss falls back, tags parse, a bad line is refused by line number.
- `crates/ui/src/egui_app/fonts_tests.rs` - the bundled face covers every
  translated string and the unit signs (Latin, `Ø`, `°`, `±`, fullwidth
  punctuation); English installs nothing; Chinese measures its own glyphs.
- `crates/ui/src/egui_app/i18n_tests.rs` - every ribbon/tree/machine string has
  a translation, the common property vocabulary is covered, every Chinese
  caption fits its cell, and Chinese is narrower in aggregate.

The visual proof is a snapshot: `egui_shell_snapshot_chinese`
(`#[ignore]`, release lane like its English twin) writes
`crates/ui/tests/snapshots/egui_app_zh.png`:

```sh
cd crates/ui && UPDATE_SNAPSHOTS=1 cargo test --lib egui_shell_snapshot_chinese -- --ignored
```

## Remaining work before this is a finished feature

1. **Hover hints** (193 strings, many long paragraphs): translate at the `hint`
   seam once the wording is settled; they are the largest block left.
2. **Diagnostics and refusals** from `crates/app`, `motion`, `sim`, `post`: each
   needs a stable name or code first, then a translated sentence - #853 requires
   the name to survive translation so tests and issue reports still match.
3. **Status line and value strings**: `state.status` is composed in
   `state.rs`; values (machine names, coolant modes, `global (no setups)`) need
   a small vocabulary pass.
4. **Panel titles** (dock tabs) - deliberately skipped here because `Tab::title`
   is also an id; the split is a small refactor.
5. **Number and unit formatting** per locale (a decimal comma must never reach a
   posted number - #853).
6. **More languages**: a catalogue file and one `REGISTRY` row; a font only if
   the script needs it. `Lang::ALL`, the locale parser, the parse-once cache and
   the View door's picker all derive from that row, and a test names any
   inconsistent entry. RTL needs egui layout work and is out of scope so far.
   Language names are native, so a reader can find their own language even in
   a language they cannot read.

## What must never be localised

Posted G-code, CL, project files, `.mch`, `.cps`, MCP tool names and their JSON,
log lines agents parse, and test goldens. No call site on those paths calls
`tr`, and the catalogue never sees them (#853's "must never be localised").
